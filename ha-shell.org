* Introduction
No one should use a GUI Terminal Emulator for a simple reason: /copying text/. Seriously? You want to use a /mouse/? Yes, you could use the =!!=, as in:

#+BEGIN_SRC sh :tangle no :eval no
  $ mkdir /foobar
  mkdir: cannot create directory ‘/foobar’: Permission denied
  $ sudo !!    # becomes: sudo mkdir /foobar
  $ cd !!$     # becomes: cd /foobar
#+END_SRC

Do you remember all of these history substitutions?

  - =!!= :: repeat the previous command.
  - =!grep= :: repeat the most recent command whose first word starts with =grep=.
  - ~!?TODO?~ :: repeat the most recent command line containing =TODO=, although I use ~C-r~ instead.
  - =!$= :: insert the /last/ argument of the previous command (=src/app.zsh= here).
  - =!:1= :: insert its first argument (=-n= here); =!:2= is the second argument.
  - =!*= :: insert all arguments from the previous command.
  - ~!!:s/TODO/FIXME/~ :: repeat the previous command, replacing its first =TODO= with =FIXME=.
  - ~^TODO^FIXME^~ :: shorthand for that kind of replacement on the previous command.

Accessing the /output/ of the commands requires knowing the expected output of the commands and writing it into files, assigning to environment variables, process substitution, or other non-visual ways to work with the textual output…otherwise, one is reaching for the mouse.

If Emacs hosts your /terminal emulator/, then you can simply drop into a /normal Emacs mode/ (hit ~C-c C-t~) and treat the text … as /text/ in a buffer.

* GhostEL with the Ghostty Library
While Emacs offers the =shell= command for running your favorite [[file:zshell.org][shell program]], I’m intrigued by both the speed and features of the [[https://github.com/dakra/ghostel][ghostel]] project, and will use it for running my /visual/ terminal applications.

#+BEGIN_SRC emacs-lisp
  (use-package ghostel
    :hook (after-init . ghostel-status-indicator-mode)
    :bind (:map project-prefix-map
                ("s" . ghostel-project)
                ("M" . ghostel-project-list-buffers))
    :config
    (add-to-list 'project-switch-commands '(ghostel-project "Ghostel") t)
    (add-to-list 'project-kill-buffer-conditions '(derived-mode . ghostel-mode))
    (add-to-list 'ghostel-eval-cmds '("magit-status-setup-buffer" magit-status-setup-buffer)))
#+END_SRC

We have the following /input states/:

  - =semi-char= : almost all keys, but not typical Emacs-keys, like ~C-x~, etc.
  - =char= (=C-c M-d=): /all/ keys go to the terminal. =M-RET= to exit.
  - *line mode* (=C-c C-l=) : supposedly no keys get sent until you press =Return=.
  - *emacs* (=C-c C-e=) and *copy mode* (=C-c C-t=) makes buffer read-only, but the latter one also freezes input.

The idea is that you want to copy, hit ~C-c C-t~, jump around to select and copy some output, and as soon as you type something, it jumps down to the prompt.

Since I’m evil,  I use the [[https://melpa.org/#/evil-ghostel][evil-ghostel]] extension which means I can go into copy mode with ~Escape~:

#+BEGIN_SRC emacs-lisp
  (use-package evil-ghostel
    :after (ghostel evil)
    :hook (ghostel-mode . evil-ghostel-mode)
    :config
    (use-package ghostel
      :config
      (defun ha/ghostel-send-C-k-and-kill ()
        "Send `C-k' to ghostel.
    Like normal Emacs `C-k'.  Kill to end of line and put content in kill-ring.
    Without this, C-k works as expected, but only in the Zsh shell."
        (interactive)
        (message "Yoinks!")
        (kill-ring-save (point) (line-end-position))

    (evil-define-key* 'insert evil-ghostel-mode-map
      (kbd "C-y") #'ghostel-send-string
      (kbd "C-s") #'consult-line
      (kbd "C-k") #'ha/ghostel-send-C-k-and-kill))
#+END_SRC

* Programmatic Interface to Shells
When I am demonstrating code at the /sprint demonstration/ I like to programmatically control a terminal. For instance, either:

#+BEGIN_SRC emacs-lisp :tangle no
  (ha-shell)
  (ha-shell-send "date")
  (ha-shell-exit)
#+END_SRC

While Ghostel offers =ghostel-project=, I keep changing emulators (dabbling with [[VTerm]] and [[Eat]]), so this function keeps a consistent interface for me:

#+BEGIN_SRC emacs-lisp
  (defun ha-shell (&optional name directory init-program)
    "Open a shell at DIRECTORY with a given NAME."
    (interactive (list nil (read-directory-name "Starting Directory: "
                                                (or (ignore-errors (project-root (project-current))) ""))))
    (let* ((default-directory (or directory default-directory))
           (ghostel-buffer-name (or name (ha-shell--default-name))))
      (ghostel)
      (when init-program
        (sit-for 1)
        (ghostel--send-string init-program)
        (ghostel-send-key "j" "ctrl"))))

  (defun ha-shell-project ()
    "Open a shell in the project's root."
    (interactive)
    (ha-shell (project-root (project-current))))
    #+END_SRC

Instead of prompting, we can make an assumption about the name for the window buffer. With the =tab-bar= running, use the name of that tab, otherwise, use the =basename= of the project’s root directory:

#+BEGIN_SRC emacs-lisp
  (defun ha-shell--default-name ()
    "Return a good name for a shell buffer.
  Based on either the name of the current tab-bar tab or the directory
  name of the active project."
    (format "*shell: %s*"
            (if tab-bar-mode
                (alist-get 'name (tab-bar--current-tab))
              (replace-regexp-in-string (rx (+? any)
                                            (group (1+ (not "/")))
                                            (optional "/") eol)
                                        "\\1"
                                        default-directory))))
#+END_SRC

The =ha-shell-send= allows me to send any command to the currently running shell … but what is that buffer? If a shell is /visible/, let’s send it to that.

What is nice is that this works with just about any shell I have open in the project, even Eshell.

#+BEGIN_SRC emacs-lisp
  (defun ha-shell-current-buffer ()
    "Return buffer of a running Shell or Eshell for the project."
    (let (result)
      (save-window-excursion
        (dolist (buf (seq-map #'window-buffer (window-list)) result)
          (switch-to-buffer buf)
          (when (apply #'derived-mode-p '(eshell-mode ghostel-mode vterm-mode term-mode eat-mode shell-mode))
            (setq result buf))))))
    #+END_SRC

Along with the ability to write an Lisp expression:  =(ha-shell-send "ls")=

Calling it /interactively/ uses a string from the copied contents on the =kill-ring= (the clipboard):

#+begin_src emacs-lisp
  (defun ha-shell-send (&optional command new-line name)
    "Send COMMAND to existing shell terminal based on DIRECTORY.
      If you want to refer to another session, specify the correct NAME.
      This is really useful for scripts and demonstrations."
    (interactive)
    (unless command (setq command (current-kill 0)))

    (save-window-excursion
      (pop-to-buffer (or name (ha-shell-current-buffer) (ha-shell--default-name)))
      (goto-char (point-max))
      (ghostel--send-string command)
      (when new-line
        (ghostel-send-key "j" "ctrl"))))
#+end_src

And a quick close and window delete:

#+begin_src emacs-lisp
  (defun ha-shell-exit (&optional name)
    "End the SSH session specified by NAME (or if not, the latest session)."
    (interactive)
    (save-window-excursion
      (switch-to-buffer (or name (ha-shell-current-buffer) (ha-shell--default-name)))
      (goto-char (point-max))
      (ghostel--send-string "exit")
      (ghostel-send-key "j" "ctrl")
      (kill-buffer name)
      (delete-window)))
#+end_src
* Shells at a Distance
As you may know, I’m big into /literate devops/ where I put my shell commands in org files. However, I also work as part of a team that for some reason, doesn’t accept Emacs as their One True Editor. At least, I am able to talk them into describing commands in Markdown files, e.g. =README.md=.

Sure, I can copy the command from the line, switch to the terminal, paste it and enter, but … why not do this process without all the keys or changing focus?
** Pushing Commands
The =ha-shell-send-line= function ties send the current command (or lines or block) to an open shell.

What does /current command/ mean? The current line? A good fall back. Selected region? Sure, if active, but that seems like more work. In a Markdown file, I can gather the entire source code block, just like in an Org file.
So the following function may be a bit complicated in determining what is this /current code/:

#+BEGIN_SRC emacs-lisp
  (defun ha-shell-send-line (prefix &optional name)
    "Send the shell command on the current line to opened shell."
    (interactive "P")
    (dolist (line (ha-shell-line-or-block prefix))
      (sit-for 0.25)
      (ha-shell-send line t name))))
    #+END_SRC

The =ha-shell-line-or-block= function converts some text in the current buffer to a list of command lines. For instance, the following code block contains a single “shell command”:

#+begin_example
 # Type the following:
 $ echo "Hello World"
 # And you will see the greeting from the most famous program.
#+end_example

If we are on the line with the =echo=, we want to grab that command, but we don’t want to Intel prompt character, =$=. If we are in an Org or Markdown file, we can get all the commands in a block.

#+BEGIN_SRC emacs-lisp
  (defun ha-shell-line-or-block (num-lines)
    "Return a list of text lines from current buffer as shell commands.

  A 'shell command' in this case is a line of text without any initial
  prompt-like characters, e.g. `$'

  If called interactively, copies the text onto the kill-ring.

  If NUM-LINES is an integer, copies that many lines.
  If NUM-LINES is nil, then follow these rules:
  If the region is active, return the lines from that.
  If in an org-mode block, return that block.
  If in a Markdown file, return the triple-back-tick code,
  or the indented code, or the inline code between single ticks.
  Otherwise, just return the current line."
    (interactive "P")
    (let ((lines (ha-shell--line-cleanup
                  (cond
                   ((and num-lines (numberp num-lines))
                    (buffer-substring-no-properties
                     (line-beginning-position) (line-end-position num-lines)))

                   ;; Region active?
                   ((region-active-p)
                    (buffer-substring-no-properties
                     (region-beginning) (region-end)))

                   ;; In org? Use the block
                   ((and (eq major-mode 'org-mode) (org-in-src-block-p))
                    (org-element-property :value (org-element-at-point)))

                   ;; In Markdown block?
                   ((and (eq major-mode 'markdown-mode) (markdown-code-block-at-point-p))
                    (buffer-substring-no-properties
                     (car (markdown-code-block-at-point-p))
                     (cadr (markdown-code-block-at-point-p))))

                   ;; In Markdown code that is just on part of the line?
                   ((and (eq major-mode 'markdown-mode) (markdown-inline-code-at-point-p))
                    (buffer-substring-no-properties
                     (car (markdown-inline-code-at-point-p))
                     (cadr (markdown-inline-code-at-point-p))))

                   (t      ; Otherwise, just grab the current line:
                    (buffer-substring-no-properties
                     (line-beginning-position) (line-end-position)))))))
      (if (called-interactively-p)
          (kill-new (string-join lines "\n"))
        lines)))
    #+END_SRC

Given text containing lines, we need to split it into individual command lines, and clean it up. This include ignoring comment lines, the initial prompt character, =$=, and any blank lines:

#+BEGIN_SRC emacs-lisp
  (defun ha-shell--line-as-command (line)
    "Return a shell command from the text in LINE."
    (let ((cmd-rx (rx string-start
                      (zero-or-more space)
                      (optional "$" (one-or-more space))
                      (group (one-or-more any))
                      (zero-or-more space))))
      (when (string-match cmd-rx line)
        (match-string 1 line))))

  (defun ha-shell--line-cleanup (str)
    "Return STR as a list of shell-command strings.
  Initial characters like `$' and `#' are removed."
    (seq-map #'ha-shell--line-as-command
             (split-string str "[\r\n]" t)))
#+END_SRC

And some tests to validate:

#+BEGIN_SRC emacs-lisp :tangle no
  (ert-deftest ha-ssh--line-cleanup-test ()
    (should (equal (ha-shell--line-cleanup "bob") '("bob")))
    (should (equal (ha-shell--line-cleanup "  bob") '("bob")))
    (should (equal (ha-shell--line-cleanup "$ bob") '("bob")))
    (should (equal (ha-shell--line-cleanup "  $  bob") '("bob")))
    (should (equal (ha-shell--line-cleanup "bob\nfoo") '("bob" "foo")))
    (should (equal (ha-shell--line-cleanup "  bob\n  foo") '("bob" "foo")))
    (should (equal (ha-shell--line-cleanup "  bob\n    foo") '("bob" "  foo"))))
#+END_SRC
** Pulling Commands
While in a Terminal window, I can use Avy and Embark to select a remote symbol (or line), and /copy/ it to the point. This works well in a normal buffer, but =ghostel= is not normal, and pasting something like that doesn’t let =ghostel= know that it should /send it/ to the terminal. So, I use my =ghostel-send-string= to do the yanking/pasting:

#+BEGIN_SRC emacs-lisp
  (advice-add 'yank :around '(lambda (orig-fun &rest args)
                                  (if (derived-mode-p 'ghostel-mode)
                                      (ghostel-send-string (current-kill 0))
                                    (apply orig-fun args))))
#+END_SRC

Can I pull a command from some buffer using Avy, and then push it into a shell terminal that isn’t the focus?

#+BEGIN_SRC emacs-lisp
  (defun ha-shell-send-avy-to-shell ()
    "Use AVY to select a visible line and send it to open shell."
    (interactive)
    (call-interactively 'avy-kill-ring-save-whole-line)
    (ha-shell-send (ha-shell--line-as-command (current-kill 0)) t))
    #+END_SRC

* Keybindings
Bind these functions under a leader sequence:

#+BEGIN_SRC emacs-lisp
  (ha-leader
    "a s"   '(:ignore t :which-key "shell")
    "a s t" '("local shell"         . ha-shell)
    "a s p" '("project shell"       . ha-shell-project)
    "p t"   '("project shell"       . ha-shell-project)
    "a s l" '("send line→shell"     . ha-send-line-to-shell)
    "a s y" '("copy code lines"     . ha-shell-line-or-block)
    "a s x" '("close shell"         . ha-shell-exit)
    "a s L" '("send any line→shell" . ha-shell-send-avy-to-shell))
#+END_SRC
